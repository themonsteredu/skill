# /gov-draft — 지원사업 문서 초안

공고문 하나를 받아 제출 가능한 초안까지 만든다. 이 커맨드는 여러 스킬을 순서대로 엮는다.

## 호출

```
/gov-draft 광주광역시 2026 여성기업 사업화 지원
/gov-draft [공고문 PDF 첨부]
/gov-draft                    # 무엇을 쓸지 되묻는다
```

## 워크플로우

각 단계마다 **멈추고 사용자 확인을 받는다.** 한 번에 끝까지 달리지 않는다.

### 1단계 — 공고 해체

공고문이 없으면 먼저 요청한다. 링크만 있으면 웹에서 가져온다.

추출할 것:
- 신청 자격 (업력, 지역, 업종, 기업 형태)
- 지원 규모 및 기간
- 제출 서류 목록
- 분량·서식 제한
- 마감 일시
- 평가 배점표
- 지원 제외 항목

**신청 자격을 먼저 검증한다.** 자격 미달이면 여기서 멈추고 알린다. 나머지 작업은 무의미하다.

### 2단계 — 주체와 문서 종류 확정

`applicant-profile` 스킬 적용. 사용자에게 명의를 묻고 프로필을 읽는다.

**체크포인트**: 판별 결과 블록을 보여주고 "이대로 진행할까요?" 확인.

### 3단계 — 배점 역산

`scoring-reverse` 스킬 적용. 형식 요건, 분량 배분, 평가항목 대응표, 가점 현황을 산출한다.

**체크포인트**: 비어 있는 근거자료 목록을 보여주고, 사용자가 지금 채울 수 있는지 묻는다. 채우면 품질이 크게 오른다.

### 4단계 — 목차 확정

문서 종류에 따라 `psst-structure` 또는 `entrust-structure` 적용. 배점 비율로 조정된 목차와 페이지 배분을 제시한다.

**체크포인트**: 목차 승인.

### 5단계 — 장별 작성

**한 장씩** 쓴다. 한 장 쓸 때마다 멈춘다.

작성 순서는 해당 구조 스킬이 지정한 순서를 따른다(대개 사실 기반 장 → 근거 기반 장 → 숫자 장).

각 장을 쓸 때 `evidence-bank`를 함께 적용해 실제 실적만 인용한다. 근거 없는 곳은 `[확인필요: ○○]`로 남기고 넘어간다. 채워 넣지 않는다.

**체크포인트**: 장마다 "다음 장으로 갈까요, 이 장을 더 손볼까요?"

### 6단계 — 통합 및 자가점검

전체를 이어붙인 뒤 확인한다:
- 분량 제한 준수 여부
- 평가항목 대응표의 모든 항목이 본문에 실제로 있는지
- 남아 있는 `[확인필요]` 개수
- 주체 서술 원칙 위반 문장이 있는지 (다른 기관 실적 혼용)

### 7단계 — 저장

`evidence-bank` 규칙에 따라 `gov-brain/past/` 저장 여부를 묻는다.

## 다음 단계 제안

작업이 끝나면 안내한다:

> 제출 전에 `/gov-review` 로 모의심사를 돌려보세요. 심사위원 시점에서 깎일 지점을 미리 찾습니다.

## 원칙

- `[확인필요]`를 그럴듯한 문장으로 덮지 않는다. 빈칸이 보여야 사용자가 채운다.
- 형식 요건 위반은 내용과 무관하게 탈락이다. 1단계에서 확인한 제한을 끝까지 지킨다.
