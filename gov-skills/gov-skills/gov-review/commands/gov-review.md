# /gov-review — 모의심사

작성한 문서를 제출 전에 심사위원 시점으로 검증한다. 탈락한 건의 원인 분석에도 쓴다.

## 호출

```
/gov-review [제안서 파일 첨부]
/gov-review 스카이교육 진로체험 위탁 건 — 왜 떨어졌는지 분석
/gov-review gov-brain/past/2025-스카이교육-진로체험.md
```

## 워크플로우

### 1단계 — 재료 확보

필요한 것:
- 검토 대상 문서
- 해당 공고문 (배점표 때문에 필수)

공고문이 없으면 요청한다. 배점표 없는 모의심사는 감상평에 그친다.

### 2단계 — 형식 요건 선검사

내용을 보기 전에 **탈락 사유부터** 확인한다. 분량, 서식, 필수 첨부, 마감. 여기 걸리면 나머지는 의미가 없으므로 즉시 알린다.

### 3단계 — 레드팀

`judge-red-team` 스킬 적용. 핵심 주장 공격 + 심사위원 유형별 검토 + 배점표 자가채점.

### 4단계 — 보완 지시서

지적사항을 **오늘 할 것 / 이번 주에 할 것 / 못 고치는 것** 세 묶음으로 정리한다.

"못 고치는 것"에는 차선책 문장을 제시한다. 예: 실적이 부족하면 → 협력기관 실적과 협약 근거로 대체.

### 5단계 — 탈락 건 분석 모드

과거 탈락 건이면 추가로:
- 공고문의 배점표와 탈락 사유(있으면)를 대조
- 같은 발주처의 선정 기관이 있으면 어떤 점이 달랐을지 추정 (추정임을 명시)
- `gov-brain/past/` 해당 파일에 **"다음에 바꿀 것"** 세 줄 기록 제안

## 원칙

- 후하게 채점하지 않는다. 본문에서 근거 문장을 못 찾으면 0점이다.
- 잘한 부분은 잘했다고 말한다. 모든 것을 문제로 만들면 우선순위가 사라진다.
- 지적 하나마다 반드시 실행 가능한 다음 행동을 붙인다.
